# lltDPO jobs on the Google Cloud T4 VM (llt-c2)

`run_exp.py` runs the lltDPO lab page's code cells 1 to 12 in one Python process, as the notebook does. It is generated by
`labs/lltDPO/make_gcp_job.py` from `labs/lltDPO/steps/` (the page code), so do not edit it: edit the steps and regenerate.
Version 2 (2026-11-08) follows the audit `llt6/lltDPO.AUDIT.md`: cells 5, 6, 8, 10, 11 and 12 changed, so rerun the smoke.

## Modes, in the order to run them

| Mode | What it runs | GPU-min (estimate) | Ledger slug |
|---|---|---|---|
| `--smoke --out outputs_smoke` | every cell at toy size, every RUN flag True: a code-path check of the final page code | about 15 | `gcp:llt-dpo-smoke` (version 2) |
| `--out outputs` (exp) | trains its own SFT model and main DPO run (no Hub dependency), step 9 off, step 10 (IPO at beta 5.0, SimPO, ORPO, KTO) and step 11 (three arms: on-policy gold, on-policy proxy, offline gold control), two judges | about 115 to 135 | `gcp:llt-dpo-exp` |
| `--defaults --out outputs_defaults` | the notebook as a learner gets it: our SFT model and adapter from the Hub, no experiment; times the default path and checks the Hub checkpoints | about 16 | `gcp:llt-dpo-defaults` |

Total about 145 to 165 GPU-min. The audit fixes added about 18 min to the exp mode: the step 11 control arm (about 10.5),
gold scoring of the 2,000 offline replies (about 3.5) and the second judge on every arm (about 4).

## Environment on llt-c2

Use the existing venv `~/llt-venv`: Python 3.12.16, torch 2.11.0+cu130 (the Kaggle build), transformers 5.22.1, trl 1.17.1,
peft 0.21.2, accelerate 1.15.0, datasets 5.1.0, bitsandbytes 0.50.2. `requirements.txt` lists the same Hugging Face pins
for a fresh venv (torch and numpy are not pip-installed). No Hub token is needed: every download is public and ungated
(Qwen/Qwen3-0.6B-Base, Qwen/Qwen3-0.6B, HuggingFaceH4/ultrafeedback_binarized, Skywork/Skywork-Reward-V2-Qwen3-1.7B,
Skywork/Skywork-Reward-V2-Llama-3.2-1B, aimlcompanion/llm-training-lab lltDPO/ and lltRewardModels/rm-s0). The `--defaults`
mode needs `lltDPO/sft-s0/` and `lltDPO/dpo-b0.1-s0/`, uploaded 2026-11-08 and verified tensor by tensor.

## Commands

```bash
# from the laptop
gcloud compute scp --project llt-capstone --zone us-central1-a --recurse courses/llm-training/gcp/llt-dpo-exp llt-c2:~/

# on the VM
cd ~/llt-dpo-exp && source ~/llt-venv/bin/activate
python -c "import torch, transformers, trl, peft; print(torch.__version__, torch.cuda.get_device_name(0), transformers.__version__, trl.__version__, peft.__version__)"
nohup python run_exp.py --smoke --out outputs_smoke > smoke.log 2>&1 &        # 1. wait for "RECORD written"
nohup python run_exp.py --out outputs > exp.log 2>&1 &                        # 2.
nohup python run_exp.py --defaults --out outputs_defaults > defaults.log 2>&1 &  # 3.
tail -f exp.log            # "CELL <name> start/end" lines and the experiment prints
```

Start a mode only after the previous one has printed `RECORD written`; two modes on one T4 would share its memory.

Resume after a Spot preemption: start the VM and run the same command again. Finished step 10 arms (`ipo-s0`, `simpo-s0`,
`orpo-s0`, `kto-s0`) and a finished step 11 are restored from `outputs/state_exp-gcp.json`. Steps 1 to 9 rerun, about
33 min in the exp mode, because they retrain the SFT model and main DPO run that steps 10 and 11 are compared against. A
preemption inside step 11 reruns all of step 11, so its three arms always come from the same samples. A resumed record says
`"restarts": N`. Remove an `outputs*` folder before rerunning a mode from scratch.

## Outputs to copy back

```bash
for m in outputs outputs_smoke outputs_defaults; do
  gcloud compute scp --project llt-capstone --zone us-central1-a --recurse "llt-c2:~/llt-dpo-exp/$m" "./courses/llm-training/kaggle/out/gcp-llt-dpo-$m"
done
```

Each folder holds `llt_dpo_<mode>.json` (the record, with per-cell peak GPU memory in `cellPeakGB`) and
`notebook_stdout_<mode>.txt` (what the cells printed). The `work_*` folders hold downloaded and saved models; skip them, or
copy only `outputs/work_exp-gcp/dpo-b0.1-s0/` (40 MB) if the retrained adapter is wanted.

## Then, on the laptop

```bash
cd courses/llm-training/labs/lltDPO
python record_gpu.py ../../kaggle/out/llt-dpo-core/llt_dpo_core.json ../../kaggle/out/gcp-llt-dpo-outputs/llt_dpo_exp-gcp.json ../../kaggle/out/gcp-llt-dpo-outputs_defaults/llt_dpo_defaults-gcp.json
../../.venv-latest/Scripts/python.exe analyze_runs.py ../../kaggle/out/llt-dpo-core/llt_dpo_core.json ../../kaggle/out/gcp-llt-dpo-outputs/llt_dpo_exp-gcp.json
```

`analyze_runs.py` needs the tokenizer and dataset (use `courses/llm-training/.venv-latest`); it analyses each session on
its own, so GCP arms are paired only with the GCP session's SFT replies.

Ledger lines in `llt5/kaggle_ledger.csv`: `start|end,<ISO time>,lltDPO,gcp:<slug>,<version>,<min>` per mode.
