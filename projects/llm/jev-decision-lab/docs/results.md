# Results

Every figure below, with the command that produced it and the caveat that limits it.

## The caveat, before any number

The tickets are generated by `src/task.py` and their labels are computed from the
five signals, so a question set that reads those five signals will always beat one
holistic question here. That is true by construction. These numbers show the
harness working end to end. They are not evidence about Jev, or about any other
model. For that, run `--backend live` against your own labelled decisions.

Every run is deterministic. Same seed, same numbers, on any machine.

## Single question against five

```
$ uv run python run.py compare
600 tickets, 300 to fit on, 300 held out.
Escalation rate 28.8%.

arm          questions  accuracy  ECE raw    +temp   +platt
-----------------------------------------------------------
single               1     0.843    0.170    0.180    0.101
decomposed           5     0.850    0.084    0.054    0.060

Lower ECE is better. Temperature only rescales, so it cannot correct a
model that leaned the wrong way. Platt scaling adds the shift that can.

What the fitted regression says each signal is worth:
  outage       2.82   The customer says the service is completely unusable right now.
  legal        2.00   The customer raises a legal, contractual or compliance concern.
  repeat       1.85   The customer says they have contacted support about this before.
  deadline     1.74   The customer names a deadline inside the next day.
  refund       0.88   The customer explicitly asks for money back.

Band that clears 95% accuracy:
  single      confidence >= 0.81, covers 49.3% of tickets at 95.3%
  decomposed  confidence >= 0.79, covers 63.0% of tickets at 95.2%
```

Accuracy moves by less than a point. What moves is the band, from 49.3% of
tickets automated to 63.0% at the same 95% accuracy bar. The fitted weights
recover the ordering the generator used, which is the check that the regression
learned this desk rather than the noise.

## The band you can automate

```
$ uv run python run.py threshold
arm           target     cut   covered  accuracy   to humans
------------------------------------------------------------
single           90%    0.78     54.3%     90.2%         137
single           95%    0.81     49.3%     95.3%         152
single           99%       -      0.0%         -         300
decomposed       90%    0.64     88.0%     90.2%          36
decomposed       95%    0.79     63.0%     95.2%         111
decomposed       99%    0.98      9.7%    100.0%         271

Coverage is the share you automate. The rest is the queue you still staff.
```

At a 99% bar the single-question arm has no band at all, so every ticket goes to a
person and the model buys nothing. The decomposed arm still automates 9.7%. That
row is the one worth carrying into a design review.

## The three primitives

```
$ uv run python run.py primitives
T0000: Hi team, I have already been passed between two agents on this ticket. We go live tomorrow morning and this blocks the launch. Thanks for reading this.

  outage       noul   0.121
  queue        choice billing  (confidence 0.72; billing 0.72, account 0.16, technical 0.11)
  frustration  score  2.37 on a 0 to 3 scale  (confidence 0.57)
```

The `queue` and `frustration` answers come from the simulated backend and carry no
meaning. The command is here to show the response shape, not a result.
