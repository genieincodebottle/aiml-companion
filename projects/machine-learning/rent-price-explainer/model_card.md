# Model Card: Rent Price Explainer

## Purpose

Teaching artifact for regression diagnostics and the interpretability trade
between a specified linear model and gradient boosting. **Not a production
pricing model and not fit for real pricing decisions.**

## Data

Synthetic. Generated by `src/rent_price_explainer/data/generate.py` from a
documented data-generating process with known coefficients (`TRUE_BETAS`).
No real listings, no personal data, no protected attributes.

The DGP deliberately contains: a log-linear functional form, size-dependent
error variance, a near-duplicate feature pair (r ≈ 0.999), a U-shaped age
effect, an influential penthouse cluster, one metro × locality interaction, and
8 pure-noise columns.

## Models

| model | specification | intended use |
|---|---|---|
| `naive_ols` | levels, all columns, non-robust SE | the "before" case |
| `specified_ols` | log target, log area, twin dropped, age curve, HC3 | the "after" case |
| `interaction_ols` | + the metro × premium interaction | the final model |
| `gbm` | HistGradientBoosting, raw columns | the challenger |

## Measured results (held-out, 1,500 listings)

| model | median APE | MAE | R² | mean abs coefficient error |
|---|---|---|---|---|
| naive_ols | 8.04% | 3,997 | 0.774 | not comparable (level target) |
| specified_ols | 4.10% | 2,675 | 0.784 | 7.9% |
| interaction_ols | 3.77% | 2,566 | 0.784 | 3.9% |
| gbm | 4.99% | 3,026 | 0.765 | no coefficients exist |

CI coverage of the true value: 83% of terms (`interaction_ols`).

## Known limitations

- **The winner is an artifact of the DGP.** The true form is parametric, which
  is exactly where a correctly specified OLS should win. On real housing data
  gradient boosting typically wins on accuracy. The transferable content is the
  workflow, not the ranking.
- Residual collinearity persists after the fixes (`bedrooms` is derived from
  area in the DGP), so `bedrooms` recovers at ~19% error and its CI does not
  cover the truth. This is genuine rather than a bug, and the docs discuss it
  rather than hiding it.
- Breusch-Pagan and RESET still flag on the specified model. Both are expected:
  HC3 is the remedy for the former, and at n=4,500 RESET detects trivial
  departures.
- No fairness analysis. The synthetic market contains no protected attributes;
  a real deployment on rental data would require one, since locality and
  crime index can proxy for them.

## Reproducibility

Fixed seeds throughout. `pytest` (32 tests) asserts that each planted violation
is still present, that the answer key never reaches fitting code, and that each
documented lesson still holds.
